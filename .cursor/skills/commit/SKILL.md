# /commit: コミット分割アシスト

## 重要ルール（最優先）

- このSkillは **git commit と git push を実行しない**。ユーザーが「OK」「実行して」「yes」と言っても、**実行用コマンドを提示するまで**に留める（ユーザーのルール: コミット&プッシュ禁止）。

## ステップ1: 変更確認

以下のコマンドを実行して現状を把握する。

```bash
git status
git diff --stat
```

必要なら追加で `git diff`（内容）も参照してよいが、まずは上記2つを必ず実行する。

## ステップ2: コミット分割案を提示

以下の形式で **必ず** 提示すること。

1. 何コミットに分けるか
2. 各コミットに含めるファイル
3. 実行できる git add と git commit -m "..." のコマンド
4. **1行でスペース区切りでファイルを並べる形式**で日本語で
5. 分割の理由（表 or 箇条書きで簡潔に）
6. コミットメッセージ規則は下記参照

### 出力テンプレ（この順番を守る）

```markdown
1. 何コミットに分けるか
   - **Nコミット**

2. 各コミットに含めるファイル
   - **Commit 1**: path/to/a path/to/b
   - **Commit 2**: path/to/c

3. 実行できる git add と git commit -m "..." のコマンド
   - **Commit 1**
     - git add path/to/a path/to/b
     - git commit -m "prefix: 日本語で変更内容を簡潔に"
   - **Commit 2**
     - git add path/to/c
     - git commit -m "prefix: 日本語で変更内容を簡潔に"

4. 1行（スペース区切り）
   - **Commit 1**: path/to/a path/to/b
   - **Commit 2**: path/to/c

5. 分割の理由
   - 箇条書き もしくは 表で簡潔に

6. コミットメッセージ規則
   - （下記ルールを厳守）
```

### コミットメッセージ規則（厳守）

| プレフィックス | 用途 |
|---|---|
| feat | 新機能追加 |
| fix | バグ修正 |
| hotfix | クリティカルなバグ修正 |
| add | 新規ファイル・機能追加 |
| update | 機能修正（バグではない） |
| change | 仕様変更 |
| clean | 整理（リファクタリング等） |
| disable | 無効化（コメントアウト等） |
| remove | 削除（ファイル） |
| upgrade | バージョンアップ |
| revert | 変更取り消し |
| docs | ドキュメント修正（README、コメント等） |
| style | コードフォーマット修正（インデント、スペース等） |
| perf | パフォーマンス改善 |
| test | テストコード追加・修正 |
| ci | CI/CD設定変更（GitHub Actions等） |
| build | ビルド関連変更（依存関係、ビルドツール設定等） |
| chore | 雑務的変更（ユーザーに直接影響なし） |

フォーマット: `プレフィックス: 変更内容を日本語で簡潔に`
例: `feat: ユーザー認証機能を追加`

## ステップ3: 確認待ち

- ユーザーが「OK」「実行して」「yes」と言ったら、**ステップ2で提示したコマンドをその順番のまま再掲**する。
- ユーザーが修正を指示したら、案を修正してから再度確認する。
- ただし「重要ルール（最優先）」により、**自動で git add / git commit は実行しない**（コマンド提示まで）。
